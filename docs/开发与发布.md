# 开发与发布

本文记录 AI 记录本插件的本地开发、测试、打包和发布流程。

## 环境要求

- Node.js 20+（建议使用当前 LTS）
- npm
- Obsidian 桌面端
- 一个独立测试 vault

不要直接在主力 vault 中开发和调试插件。AI 记录本会读写 vault 文件、创建目录、移动软删除文件，开发期应使用专门测试库。

## 安装依赖

```bash
npm install
```

## 开发构建

```bash
npm run dev
```

该命令使用 esbuild 进行开发构建。开发时可将构建产物复制或链接到测试 vault 的插件目录：

```text
<测试 vault>/.obsidian/plugins/ai-notebook/
  manifest.json
  main.js
  styles.css
```

Obsidian 中禁用再启用插件，或重启 Obsidian，即可加载新构建。

## 生产构建

```bash
npm run build
```

构建流程：

1. `tsc -noEmit -skipLibCheck` 做 TypeScript 类型检查。
2. `node esbuild.config.mjs production` 生成生产版 `main.js`。

## 自动化测试

```bash
npm test
```

测试基于 Vitest，覆盖领域逻辑、基础设施适配、AI 整理管线、移动网页桥等。测试使用 memory vault/mock，不依赖 Obsidian GUI。

常用测试命令：

```bash
npm test
npm run test:watch
```

## 打包安装目录

```bash
npm run package
```

该命令会先执行生产构建，然后复制运行文件到：

```text
release/ai-notebook/
  manifest.json
  main.js
  styles.css
  README.txt
```

同时归档到：

```text
release/history/v<version>/
```

`release/history/CATALOG.md` 会记录已生成的历史包。

## 本地安装 / 更新

将 `release/ai-notebook` 整个文件夹复制到：

```text
<你的 vault>/.obsidian/plugins/ai-notebook/
```

更新时注意：

- 可以覆盖 `manifest.json`、`main.js`、`styles.css`。
- 不要删除目标插件目录中的 `data.json`。
- 更新后在 Obsidian 中禁用再启用插件，或重启 Obsidian。

## 版本发布流程

1. 更新 `manifest.json` 和 `package.json` 中的版本号。
2. 如适用，更新 `versions.json`。
3. 运行测试：

   ```bash
   npm test
   ```

4. 运行构建：

   ```bash
   npm run build
   ```

5. 打包：

   ```bash
   npm run package
   ```

6. 检查 `release/ai-notebook` 和 `release/history/v<version>`。
7. 提交并打 tag。
8. 推送到 GitHub。

## 安全发布检查

发布或提交前至少确认：

- 没有提交 `data.json`、API Key、token 或私人 vault 内容。
- `.gitignore` 覆盖 `node_modules/`、构建 sourcemap、IDE 配置、本机数据。
- AI Provider 示例不包含真实密钥。
- 公网入口文档提醒用户 token 泄漏风险。
- 蓝图变更仍走校验 + Diff 确认。
