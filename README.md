# AI 记录本（ai-notebook）

本地优先的 Obsidian 插件：用**可版本化能力蓝图（Blueprint）**定义每本记录本的能力；同一插件可运行多个互不干扰的 AI 记录本。条目以 Markdown 落盘，**功能版本回滚不会改写用户笔记内容**。

| **最低 Obsidian** | `1.5.0` |

## 0.2.0 亮点

相对 `0.1.x`，本版重点强化**可交互助手**与**可恢复的对话附件**：

| 能力 | 说明 |
|------|------|
| **浮层 AI 对话** | 可拖拽、缩放、收放；默认仅右下角「助手」按钮，避免挡内容 |
| **助手真写入** | 改正文/字段、新建条目；图片/视频可 `embed_in_body` 写入正文并可预览播放 |
| **本轮附件隔离** | 本轮命令只针对本轮上传，不再把历史上传误混进「本轮附件」 |
| **拖拽 / 粘贴上传** | 输入区支持拖入文件、Ctrl+V 粘贴截图 |
| **上传即落盘** | 对话附件写入可配置目录，历史可打开 / 多选下载 |
| **按条目的助手历史** | 每条笔记独立会话；「新对话」真正新建；进入条目默认接续最近会话 |
| **多模型有序回退** | 规划 / 助手 / 语音各可配顺序 1→2→3；看图能力失败自动切换 |
| **记录本 / 条目选择** | 浮窗内切换上下文，与主界面双向同步 |

## 功能总览

### 记录本与数据

- **多实例记录本**：独立目录、蓝图版本、条目列表、收藏柜  
- **模板**：文献 / 灵感 / 会议 / 收藏向 / 空白  
- **Markdown 存储**：`items/*.md`，可被 Obsidian 搜索、同步、备份  
- **列表 / 表格 / 看板**：由蓝图 `views` 驱动，可筛选排序  

### 蓝图与版本

- 能力由 `blueprints/vNNNN.json` 描述  
- 手动提交版本、历史恢复、Diff 确认  
- 回滚蓝图**不改写**已有条目正文（未映射字段保留）  

### AI 能力

| 模式 | 对象 | 典型用途 |
|------|------|----------|
| **助手** | 当前（或选中的）**条目** | 改正文、插图/视频、描述画面、整理内容 |
| **改功能** | **整本记录本的蓝图** | 加字段、改视图、开收藏柜等「小插件」级能力 |
| **整理** | 条目 / 收件箱 | 杂乱文本 → 字段 + 分层正文 |
| **语音** | 录音 | Whisper / 兼容 transcriptions，或聊天多模态听音频 |

### 跨端

- 收件箱 `AI Inbox/pending` → AI 整理进本  
- 局域网手机网页入口  
- Cloudflare / ngrok 等公网隧道（可选）

## 安装与更新

### 方式 A：从 GitHub Release 安装（推荐，开箱即用）

1. 打开 [Releases](https://github.com/ZNaiGaomu/AI-notebook/releases)  
2. 下载 **`ai-notebook-vX.Y.Z.zip`**（Release 附件，不是 Source code）  
3. 解压后应直接看到：

```text
manifest.json
main.js
styles.css
（可能还有 README.txt）
```

4. 将上述文件放到：

```text
<你的 Obsidian 库>/.obsidian/plugins/ai-notebook/
```

文件夹名建议为 **`ai-notebook`**（与插件 ID 一致）。

5. Obsidian → **设置 → 社区插件** → 关闭「受限模式」→ 启用 **AI 记录本**  
6. （可选）在插件设置中添加 AI 服务商（Base URL + API Key + 模型）

### 方式 B：从 Tag 页面下载「Source code」压缩包（需自己找到构建产物）

在 [Tags](https://github.com/ZNaiGaomu/AI-notebook/tags) 点 `v0.2.0` 的 **zip / tar.gz**，下载的是**整个源码仓库快照**，**不能**把解压根目录整夹当插件用。

正确用法：

1. 解压 Source code  
2. 进入其中的构建好的安装目录：

```text
AI-notebook-0.2.0/          （解压后的仓库根，名称可能略有不同）
  └── release/ai-notebook/
        ├── manifest.json
        ├── main.js
        ├── styles.css
        └── README.txt
```

3. **只复制** `release/ai-notebook/` 里的运行文件到：

```text
<你的库>/.obsidian/plugins/ai-notebook/
```

4. 启用插件（同上）

> **对比**  
> | 下载物 | 能否直接当插件 |  
> |--------|----------------|  
> | Release 附件 `ai-notebook-v0.2.0.zip` | ✅ 解压即装 |  
> | Tag / Code 的 Source code zip | ❌ 需进到 `release/ai-notebook/` 再装 |  
> | 源码根目录（含 `src/`、`package.json`） | ❌ 需 `npm run build` 后才有 main.js |

若你本机已 clone 仓库，也可直接复制：

```text
release/ai-notebook/  →  .obsidian/plugins/ai-notebook/
```

### 更新插件

- 覆盖目标目录中的 `manifest.json`、`main.js`、`styles.css`  
- **不要删除** `data.json`（本机 API Key、Provider、路径设置等）  
- 更新后建议：禁用再启用插件，或重启 Obsidian  

### 从源码自己构建

```bash
git clone https://github.com/ZNaiGaomu/AI-notebook.git
cd AI-notebook
npm install
npm test
npm run package
```

然后将 `release/ai-notebook/` 复制到 plugins 目录。

开发时：

```bash
npm run build    # 生产构建并同步到 release/ai-notebook
npm run dev      # watch，改代码后自动同步
```

## 隐私与数据边界（开源 ≠ 公开你的库）

### 仓库 / Tag / Release 里有没有你的密钥？

对当前仓库做了扫描（含常见 `sk-`、私钥头、`data.json` 等），**未发现真实 API Key 或私人笔记被提交进 Git**。

| 内容 | 是否在开源仓库中 |
|------|------------------|
| 插件源码与构建的 `main.js` | ✅ 公开（给别人部署用） |
| 你的 API Key | ❌ 只在你本机 `data.json` / 用户配置，且已在 `.gitignore` |
| 你的笔记、条目、对话历史、上传文件 | ❌ 只在你的 Obsidian 库里 |

别人 star / 下载 Tag / 下载 Source code，得到的是**空配置的软件**，需要他们自己在设置里填自己的 Key。

### 什么时候内容会离开你的电脑？

仅当你在本机配置了 AI 并调用时，请求会发往**你填写的**服务商（OpenAI 兼容接口等），可能包含对话、条目摘要、图片等——这是「你 → 你的 API 提供商」，**不是**「你 → 其他 GitHub 用户」。

### 部署者需要知道的

- 自己准备 OpenAI 兼容的 Base URL 与 API Key  
- 配置只保存在**自己的**库 / 本机  
- 不要把带真实 Key 的 `data.json` 提交到公开仓库

## 浮层助手（写笔记）

### 窗口

- 默认 **收起** 为右下角按钮  
- 可拖标题栏、右下角缩放；**尺寸/位置会记住**  
- 内含：助手 / 改功能、历史、新对话、记录本与条目选择  

### 写入规则（摘要）

- **默认**上传仅供参考，不自动进笔记  
- 明确说「插入正文 / 放进笔记」→ `embed_in_body`（正文 `![[path]]`，可预览/播视频）  
- 明确说「收藏柜」→ 才进收藏柜  
- **本轮附件**只含本轮上传；成功嵌入后从内存会话缓存移除（盘上历史文件仍在）  

### 历史（按条目）

- 助手历史绑定 **当前条目**  
- 进入条目默认 **接续最近会话**  
- **新对话**会真正新建线程（不会写回旧会话）  
- 每条会话：**打开** 进入对话；**附件…** 多选打开/下载该会话全部上传  

### 追加发送

- **排队**：上一条结束后自动发下一条  
- **引导**：补充到当前进行中的请求

## 改功能（改蓝图）

- 对象是整本记录本的 **功能配置**，不是某一条笔记正文  
- AI 生成完整蓝图 JSON → 校验 → **Diff 确认** → 提交新版本  
- 历史按 **记录本** 保存，不必按条目拆分

## AI 与多模型路由

设置 → **AI 服务商与模型** → **用途 → 服务商（有序回退）**：

| 用途 | 典型用途 |
|------|----------|
| 改功能 / 规划 | 蓝图编译 |
| 整理 / 助手 | 条目助手、看图、整理 |
| 语音转写 | Whisper 等 STT |

每个用途可配 **顺序 1 / 2 / 3**（不同服务商 + 模型）。前一个失败或不支持所需能力（如视觉）时自动尝试下一个。

支持 OpenAI 兼容 Base URL + API Key；可从上游拉取模型列表、测试连通。

## 附件、历史与路径设置

| 设置项 | 说明 |
|--------|------|
| 记录本根目录 | 默认 `AI Notebooks` |
| 附件根目录 | 条目嵌入等，默认 `attachments/ai-notebook` |
| **对话上传保存位置** | 默认 `{附件根}/chat-uploads`；可用 **选择文件夹…** 选电脑任意盘符路径 |
| **对话附件保留** | 默认永久；可关永久后填天数（清理策略可扩展） |
| 手机收件箱 | 默认 `AI Inbox` |

对话附件：一点上传/粘贴/拖入即写入配置目录，供历史二次打开下载；与「是否写入笔记正文」无关。

## 手机与收件箱

1. **同步收件箱**：手机写到 `AI Inbox/pending`，电脑端「处理收件箱」  
2. **局域网网页**：电脑启动入口，同 Wi‑Fi 打开链接写字/录音  
3. **公网隧道**：Cloudflare / ngrok 等（需本机工具）  

详见插件设置中的「手机网页入口」与命令面板相关项。

## 注意与隐私

- API Key 保存在插件 `data.json` / 库内用户配置，**不写入**笔记正文  
- 对话上传可存到库内或用户指定目录；默认永久保留  
- 助手写入会真实修改 Markdown，请定期备份库  
- 公网隧道会暴露访问入口，请妥善保管链接与 token
