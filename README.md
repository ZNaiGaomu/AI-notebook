## 只要这一小份就能用

**结论：只需要 `release/ai-notebook/` 里的文件，不必下载/解压整个仓库。**

仓库里还有 `src/`、`docs/`、`tests/` 等，那是**开发与构建**用的。插件运行时已经打进 `main.js`，**不依赖** GitHub 仓库、不依赖源码目录，也和别人的密钥/笔记无关。

### 最终只要这 3 个文件

```text
.obsidian/plugins/ai-notebook/
  ├── manifest.json   # 插件身份与版本
  ├── main.js         # 全部逻辑（已打包）
  └── styles.css      # 样式
```

| 你拷什么 | 能否正常运行 |
|----------|----------------|
| **仅** `release/ai-notebook/`（上面 3 个文件） | ✅ 可以 |
| 整个仓库（源码 + 文档 + 测试） | 能 clone，但**装插件时用不到**，纯多余 |
| Tag 的 Source code 整夹当插件目录 | ❌ 不行（须进入 `release/ai-notebook/`） |

### 最短安装步骤

1. 取得安装文件（任选其一）：
   - **推荐**：Releases 里的 `ai-notebook-vX.Y.Z.zip`（解压即是这 3 个文件）  
   - 或：仓库 / 本机路径里的 [`release/ai-notebook/`](release/ai-notebook/)  
   - 或：Tag 的 Source code zip → **只进入**其中的 `release/ai-notebook/`  
2. 复制到：`<你的库>/.obsidian/plugins/ai-notebook/`  
3. 设置 → 社区插件 → 关闭受限模式 → 启用 **AI 记录本**  
4. （可选）在插件设置里自己填 Base URL、API Key、模型  

**更新**：只覆盖这 3 个文件；**不要删** 同目录下的 `data.json`（你自己的 Key 与设置）。

## 0.6.0 亮点（第六版）

相对 `0.5.0`，本版把**附件管理**从收藏柜中拆出来，并修好收件箱整理后媒体不可预览的问题。

| 能力 | 说明 |
|------|------|
| **独立附件管理** | 「附件」页签 + `attachments/index.json`；普通上传不进收藏柜 |
| **按条目标题分类** | 目录形如 `attachments/ai-notebook/{记录本标题}/items/{条目标题}/` |
| **改名跟随** | 条目改标题后，附件文件夹名同步，并尽量修正正文 `![[旧路径]]` |
| **粘贴/拖入归类** | 条目正文里粘贴、拖入的文件会吸入该条目附件目录 |
| **删除互不影响** | 默认解除登记保留文件与正文；删正文不删附件实体 |
| **收件箱跨本整理** | 可选目标记录本 / 已有条目 / 新建条目 |
| **收件箱媒体可预览** | 仅收件箱也保存原文件；整理进条目后可看图、视频、听音频 |
| **收藏柜回归可选** | 链接与主动收藏；不再承担普通附件流水线 |

## 功能总览

### 记录本与数据

- **多实例记录本**：独立目录、蓝图版本、条目列表、收藏柜  
- **模板**：文献 / 灵感 / 会议 / 收藏向 / 空白  
- **Markdown 存储**：`items/*.md`，可被 Obsidian 搜索、同步、备份  
- **手工条目吸收**：在 `items/` 下手工新建 `.md` 会自动成为条目；非 Markdown 文件会生成引用型条目
- **列表 / 表格 / 看板**：由蓝图 `views` 驱动，可筛选排序（仅一种视图时不显示多余模式按钮）  

### 蓝图与版本

- 能力由 `blueprints/vNNNN.json` 描述  
- **另存蓝图版本**、历史恢复、Diff 确认  
- 回滚蓝图**不改写**已有条目正文（未映射字段保留）  

### AI 能力

| 模式 | 对象 | 典型用途 |
|------|------|----------|
| **助手** | 当前（或选中的）**条目** | 改正文、插图/视频、描述画面、整理内容 |
| **改功能** | **整本记录本的蓝图** | 加字段、改视图、开收藏柜等「小插件」级能力 |
| **整理** | 条目 / 收件箱 | 杂乱文本 → 字段 + 分层正文 |
| **语音** | 录音 | Whisper / 兼容 transcriptions，或聊天多模态听音频 + 可选润色 |

### 插件安装包历史（0.3.0）

- 多 GitHub 来源拉取 Tags / Release / 默认分支 ZIP  
- 本地备份列表 + 一键切换  
- **永不**因拉取而改当前运行包；切换不碰 `data.json` 与笔记  

### 附件与收藏

- **附件管理**（0.6.0）：分类保存、正文嵌入预览、删除互不影响  
- **收藏柜**：可选链接/文件收藏，与普通上传分离  

### 跨端

- 收件箱 `AI Inbox/pending`（及 `files/` 二进制）→ 可选跨本 / 指定条目整理  
- 手机端可选择记录本或记录本下已有条目：选记录本=新建条目，选已有条目=追加正文末尾
- 手机端可新建记录本、在记录本下新建命名条目
- 普通手机文件上传 → 附件目录 + 正文嵌入；「仅收件箱」保留原文件待整理
- Tailscale 虚拟局域网手机入口（推荐稳定）
- 局域网手机网页入口  
- Cloudflare / ngrok 等公网隧道（可选）

## 快速上手

1. Ribbon 点击 **AI 记录本**，或命令「打开 AI 记录本」  
2. **新建记录本** → 选模板  
3. 用 **语音录入**、浮层 **助手**、手机入口，或直接在 `items/` 文件夹手工新建条目
4. 右下角 **助手** → 上传图/视频 →「插入正文并描述」  
5. 需要改结构能力时切到 **改功能**，确认 Diff 后应用  
6. **历史版本** → 可管本内蓝图，或配置 GitHub 来源切换插件安装包

## 浮层助手（写笔记）

### 窗口

- 默认 **收起** 为右下角按钮  
- 可拖标题栏、右下角缩放；**尺寸/位置会记住**  
- 内含：助手 / 改功能、历史、新对话、记录本与条目选择  

### 写入规则（摘要）

- **默认**上传仅供参考，不自动进笔记  
- 明确说「插入正文 / 放进笔记」→ `embed_in_body`（正文 `![[path]]`）  
- 明确说「收藏柜」→ 才进收藏柜  
- **本轮附件**只含本轮上传  

### 历史（按条目）

- 助手历史绑定 **当前条目**  
- 进入条目默认 **接续最近会话**  
- **新对话**会真正新建线程  

### 追加发送

- **排队**：上一条结束后自动发下一条  
- **引导**：补充到当前进行中的请求

## 改功能（改蓝图）

- 对象是整本记录本的 **功能配置**，不是某一条笔记正文  
- AI 生成完整蓝图 JSON → 校验 → **Diff 确认** → 提交新版本  
- 工具栏 **「另存蓝图版本」** 会把当前配置手动提交进 **本内功能历史**  
- **「恢复此本内版本」** 会再提交一条指向旧配置的新版本（历史可追溯）

## 历史版本：本内蓝图 + 插件安装包

打开工具栏 **历史版本**，两条独立时间线：

### 本内功能历史

- 只改当前记录本的 `blueprints/`  
- 与「另存蓝图版本」同一条线  
- **不改** items 笔记正文  

### 插件整体历史

三条线互不混用：**本地备份**、**每个 GitHub 来源各自列表**、**本机 manifest 版本号**。  
「仅版本号相同」**不等于**正在使用某个远程包；只有你点过 **使用 / 切换** 成功后，才标记 **当前使用**。

#### 1）GitHub 版本来源（多行，仿 AI 服务商）

1. 填写 **显示名称** + **仓库链接**（如 `https://github.com/ZNaiGaomu/AI-notebook`）→ 添加  
2. **拉取版本**（只更新该来源的可选列表，**绝不改当前运行包**）  
3. **打开版本** → 看说明与拉取方式 → **下载到本地** / **下载并使用**  

拉取按**优先级**（前一通道有结果就停，不混通道）：

| 优先级 | 方式 | 卡片标注 |
|--------|------|----------|
| **1** | **Release 安装包附件**（如 `ai-notebook-*.zip`） | `Release 附件` |
| **2** | 无可用 Release 包时 → **Tags 源码 zip** | `Tags 源码包` |
| **3** | Tags 也没有 → **Code → Download ZIP**（默认分支最新，通常 1 条） | `Code Download ZIP` |

- 每条版本会标明 **拉取方式** 与状态：`未下载` / `已下载（未应用）` / `当前使用（已从本条应用）`  
- 下载路径（同号不同源隔离）：

```text
.obsidian/plugins/ai-notebook/package-archive/by-source/{sourceId}/vX.Y.Z/
```

#### 2）本地运行备份（独立列表）

- **立即备份当前安装包** → 下方出现卡片 → **切换到此本地备份**  
- 路径：`package-archive/vX.Y.Z/`（与 GitHub 来源分开）  
- 启动自动备份：若本地**已有当前版本**则跳过，避免冗余  
- 只有从**某条本地备份**切换成功，才在该卡片标「当前使用」  

#### 当前使用 vs 本机版本号

| 显示 | 含义 |
|------|------|
| 本机 manifest 版本 | 当前装在插件目录的版本号（事实） |
| 当前使用 | 你最后一次从历史页 **应用成功** 的来源 + 版本（未应用过则明确写「尚未应用」） |

#### 切换安全边界

- 只会覆盖：`main.js` / `manifest.json` / `styles.css`  
- **不修改** `data.json`，**不改** vault 笔记  
- 切换后请 **禁用再启用** 本插件，或重启 Obsidian

## AI 与多模型路由

设置 → **AI 服务商与模型** → **用途 → 服务商（有序回退）**：

| 用途 | 典型用途 |
|------|----------|
| 改功能 / 规划 | 蓝图编译 |
| 整理 / 助手 | 条目助手、看图、整理 |
| 语音转写 | Whisper 等 STT |

每个用途可配 **顺序 1 / 2 / 3**。支持 OpenAI 兼容 Base URL + API Key；可拉模型列表、测试连通。

## 手机与收件箱

1. **定向写入**：手机端先选记录本，再选“新建条目”或已有条目；已有条目会追加到正文末尾  
2. **手机新建记录本 / 条目**：无需回电脑端，也能创建记录本和命名条目
3. **同步收件箱**：手机写到 `AI Inbox/pending`，电脑端「处理收件箱」  
4. **Tailscale 虚拟局域网**：电脑和手机登录同一 Tailscale 后，复制 `100.x` 链接即可打开
5. **局域网网页**：电脑启动入口，同 Wi‑Fi 打开链接写字/录音
6. **公网隧道**：Cloudflare / ngrok 等（需本机工具）

## 隐私与数据边界

### 开源仓库里有什么 / 没有什么

| 内容 | 是否在 GitHub 仓库中 |
|------|----------------------|
| 源码、`main.js` 安装包 | ✅ 有（供他人自行部署） |
| 你的 API Key | ❌ 无（只在本机 `data.json`，已 gitignore） |
| 你的笔记 / 对话 / 上传文件 | ❌ 无（只在你自己的 Obsidian 库） |

### 数据何时会离开本机

- 配置了 AI 并调用时 → 请求发往**你填写的**服务商  
- 使用「拉取版本 / 下载安装包」时 → 请求 GitHub / jsDelivr 等公开元数据与 zip（**不上传**你的笔记）  

### 使用者注意

- 自行准备 OpenAI 兼容 Base URL 与 API Key  
- 不要把含真实 Key 的 `data.json` 提交到公开仓库  
- 助手写入与插件切换都会改本地文件，请备份库
